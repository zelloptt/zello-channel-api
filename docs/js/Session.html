getHistory(optionsopt, userCallbackopt) → {promise}

Reads the channel's stored history. Available on Zello Work networks with offline channel messages enabled; status events report it as history_supported. The server keeps the last 24 hours, at most 50 messages per request, and this method returns metadata only: replay a voice entry with playHistoryMessage and fetch an image with getHistoryImage.
Parameters:
Name Type Attributes Default Description
options object <optional>
 history options
userCallback function <optional>
 null callback that is fired with the history or an error
Properties:
Name Type Attributes Description
options.since Number <optional>
 Unix timestamp in milliseconds of the newest message the client already holds; omit or pass 0 for everything the server kept
options.channel String <optional>
 channel to read, defaults to the session channel
Source:
  • session.js, line 780
Returns:
promise that resolves with {success, channel, messages}, oldest message first, each carrying type (audio, text, image, location or alert), message_id, from, ts and the type's own fields; rejects on error, with 'busy' while another history request is still in flight and 'not supported' where history is unavailable
Type
promise
Example
session.getHistory({ since: 1758300000000 }).then(function(result) {
     result.messages.forEach(function(message) {
       console.log(message.type, message.from, message.ts);
     });
   });

getHistoryImage(messageId, optionsopt, userCallbackopt) → {promise}

Fetches one stored image from the channel history. The server downloads it and delivers it like a live one: incoming_image fires with an IncomingImage whose data carries the message_id, and the thumbnail and full image follow on that instance.

Properties:
Name Type Attributes Description

options.channel String <optional>
 channel the message belongs to, defaults to the session channel
Source:

getUserProfiles(usernames, userCallbackopt) → {promise}

Requests the profiles of the given users. Requires the session to be created with features: { profiles: true }. The command only acknowledges the request: each profile arrives as a separate user_profile event, cached ones right away and the rest once the server has fetched them.

playHistoryMessage(messageId, optionsopt, userCallbackopt) → {promise}

Replays one stored voice message from the channel history. The server downloads the recorded audio and delivers it like any incoming voice message: incoming_voice_will_start fires with a message whose data carries message_id, followed by the audio and incoming_voice_did_stop.
